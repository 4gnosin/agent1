# 4gnosin.github.io - GENERATOR PROMPT: ΑΣΚΗΣΕΙΣ & ΟΜΑΔΕΣ (window.GROUPS & window.EXERCISES)

Εργάζεσαι στο αποθετήριο του στατικού εκπαιδευτικού site **4gnosin.github.io** (GitHub Pages) με ελληνικές σημειώσεις και διαδραστικές ασκήσεις για μαθήματα Μηχανολογίας ΕΠΑ.Λ.
Στόχος είναι η δημιουργία διαδραστικών ασκήσεων βασισμένων στην επίσημη **Τράπεζα Θεμάτων Διαβαθμισμένης Δυσκολίας του Ι.Ε.Π.** και στα σχολικά βιβλία, που καλύπτουν τη θεωρία με σαφήνεια, ακρίβεια και διδακτική αξία.

## 1. ΤΕΧΝΙΚΗ ΠΡΟΔΙΑΓΡΑΦΗ: `groups.js`

```javascript
window.GROUPS = window.GROUPS || [];
window.GROUPS.push(
  {
    "id": "<chNN-SS-slug>",      // ΥΠΟΧΡΕΩΤΙΚΑ: ch{Κεφάλαιο:02d}-{Υποκεφάλαιο:02d}-{slug}
                                 // π.χ. "ch02-04-psychrometry", "ch02-10-exartimata", "ch08-02-rolos-klimatistikon-monadon"
                                 // ΟΧΙ tf/mc/calc
    "chapter": "<chapter_num>",  // π.χ. "2"
    "title": "<Υποενότητα ύλης>", // π.χ. "2.4 Η αποτύπωση των θερμοδυναμικών χαρακτηριστικών"
    "blurb": "<Σύντομη περιγραφή των θεμάτων της υποενότητας>"
  }
);
```

```javascript
  "layout": "unified",           // όλα τα υποερωτήματα ορατά μαζί — χωρίς gating

  // [Μόνο για "calc"]:

    { "label": "F", "value": "12000 N" },
    { "label": "d₁", "value": "10 mm" }
  ],
  "items": [
    // Πίνακας με τα υποερωτήματα
  ]

```

## 3. ΕΠΙΤΡΕΠΟΜΕΝΑ ΕΙΔΗ ΑΣΚΗΣΕΩΝ (`items[].kind`)

### Α. Πολλαπλής Επιλογής (`mc`)
```javascript
{
  "kind": "mc",
  "prompt": "Ποιο είναι το προφίλ γωνίας του τυποποιημένου μετρικού σπειρώματος ISO;",
  "options": [
    { "id": "a", "text": "55°" },
    { "id": "b", "text": "60°" },
    { "id": "c", "text": "90°" },
    { "id": "d", "text": "45°" }
  ],
  "answer": "b",
  "explain": "Το τυποποιημένο μετρικό σπείρωμα κατά ISO έχει γωνία προφίλ 60°. Η γωνία 55° αφορά το σπείρωμα Whitworth."
}
```

### Β. Σωστό / Λάθος (`tf`)
```javascript
{
  "kind": "tf",
  "prompt": "Οι ηλωτές συνδέσεις (πριτσινώματα) ανήκουν στις λυόμενες συνδέσεις.",
  "answer": false,
  "explain": "Λάθος. Οι ηλώσεις είναι μόνιμες (μη λυόμενες) συνδέσεις, διότι για την αποσυναρμολόγησή τους απαιτείται καταστροφή των ήλων."
}
```

### Γ. Αντιστοίχιση (`match`)
```javascript
{
  "kind": "match",
  "prompt": "Αντιστοιχίστε το μέσο σύνδεσης με την κατηγορία του:",
  "left": [
    { "id": "1", "text": "Κοχλίας και περικόχλιο" },
    { "id": "2", "text": "Ήλος (πριτσίνι)" }
  ],
  "right": [
    { "id": "a", "text": "Μόνιμη (μη λυόμενη) σύνδεση" },
    { "id": "b", "text": "Λυόμενη σύνδεση" }
  ],
  "pairs": {
    "1": "b",
    "2": "a"
  },
  "explain": "Ο κοχλίας προσφέρει λυόμενη σύνδεση, ενώ οι ήλοι είναι μη λυόμενες (μόνιμες) συνδέσεις."
}
```

**Σημαντικός Κανόνας για Ασκήσεις Αντιστοίχισης (`match`) με Σχήμα/Διάγραμμα:**
- Όταν η Στήλη Α αναφέρεται σε σχήμα/διάγραμμα με αριθμημένα βέλη ή γραμμές (π.χ. 1, 2, 3, 4):
  - Στο `left`, τα κείμενα `text` πρέπει να είναι ΑΥΣΤΗΡΑ ΚΑΙ ΜΟΝΟ τα ονόματα/αριθμοί όπως ορίζονται στην εκφώνηση (π.χ. "Γραμμή 1" ή απλώς "1", "Γραμμή 2" κ.ο.κ.).
  - ΑΠΑΓΟΡΕΥΕΤΑΙ αυστηρά να προστίθενται δικές σου επεξηγήσεις σε παρενθέσεις (π.χ. "(καμπύλη)", "(οριζόντια προς τα δεξιά)", "(απότομη πλάγια)"), διότι προδίδουν τη λύση και αλλοιώνουν την πρωτότυπη άσκηση της Τράπεζας Θεμάτων!


### Ε. Υπολογιστικό υποερώτημα (`calc`) & μαθηματικά
Κάθε υπολογιστικό μέρος είναι ένα item μέσα στο ίδιο θέμα. Μην κρύβεις τα επόμενα μέρη πίσω από «βήματα».
Κάθε υπολογιστικό μέρος είναι ένα item μέσα στο ίδιο θέμα. Μην κρύβεις τα επόμενα μέρη πίσω από «βήματα».

**Μαθηματικά σύμβολα & KaTeX (υποστηρίζονται πλήρως παντού: stem, prompt, formula, hint, explain):**
- Για μεταβλητές, δείκτες και τύπους γράφε σε LaTeX με delimiters `$ ... $` ή `\\( ... \\)`:
  π.χ. `$t_{db1} = 31\\text{ }^\\circ\\text{C}$`, `$\\phi_1 = 80\\%$`, `$\\Delta h_T$`, `$\\Delta h_S$`, `$h_1$`, `$h_2$`, `$W_1$`, `$v_1$`, `$Q_L$`, `$\\text{SHR}$`.
- ΜΗΝ αφήνεις άκομψα strings κώδικα όπως `t_db1` ή `\\Delta h_T` χωρίς `$ ... $`. Το site τα μετατρέπει αυτόματα σε όμορφα μαθηματικά σύμβολα μέσω KaTeX!
- Τα `code` / `title`: γράφε απλά `Θέμα 4ο` (χωρίς `<sup>`). Το site προσθέτει μόνο του τον ανώτερο δείκτη.

```javascript
{
  "kind": "calc",
  "prompt": "Υπολογίστε την επιτρεπόμενη δύναμη εφελκυσμού $F$ του κοχλία.",
  "formula": "$F = \\sigma_{\\text{επ}} \\cdot A_1$",
  "answer": 6400,
  "unit": "N", // Καθαρή μονάδα μέτρησης (π.χ. "°C", "bar", "m/s", "kJ/kg", "N") — ΠΟΤΕ ακατέργαστο LaTeX code όπως "^\circ\text{C}"
  "tolerance": 0.02,
  "hint": "Χρησιμοποιήστε τον τύπο $F = \\sigma_{\\text{επ}} \\cdot A_1$.",
  "explain": "Η δύναμη υπολογίζεται από: \\( F = 80\\text{ N/mm}^2 \\cdot 80\\text{ mm}^2 = 6400\\text{ N} \\)."
}
```
## 4. ΚΑΝΟΝΕΣ ΠΟΙΟΤΗΤΑΣ & ΕΠΑΛΗΘΕΥΣΗΣ
1. **Υποχρεωτική Επεξήγηση (`explain`):** Κάθε ερώτημα ΠΡΕΠΕΙ να περιέχει σαφή εξήγηση για να μαθαίνει ο μαθητής από το λάθος του.
2. **Σύνδεση με Θεωρία:** Το πεδίο `"theory"` πρέπει να συνδέεται με υπαρκτό `slug` θεωρίας.
3. **Escapes:** Στο JavaScript string, τα backslashes του LaTeX (μόνο στο `explain`) πρέπει να είναι διπλά (`\\\\sigma`, `\\\\text`).
4. **Πιστή μετατροπή πηγής — ΚΑΜΙΑ παράλειψη:** Εντόπισε **όλες** τις εκφωνήσεις. Αν δεν γίνεται πλήρως διαδραστικό (π.χ. σχέδιο P–V), βάλε εκφώνηση + ό,τι ελέγχεται· **ποτέ μην παραλείπεις ολόκληρο θέμα**.
5. **Πηγή από PDF (σπασμένο κείμενο):** Το MD μπορεί να έχει artifacts εξαγωγής. **Απαγορεύεται** να επινοείς αριθμούς, τύπους ή φυσική που δεν τεκμηριώνονται στην εκφώνηση ή στην «ΕΝΔΕΙΚΤΙΚΕΣ ΑΠΑΝΤΗΣΕΙΣ». Για `calc`, το `answer` βγαίνει **μόνο** από ρητούς αριθμούς της λύσης/εκφώνησης. Αν η λύση είναι ασαφής, προτίμησε mc/tf με βάση το κείμενο της λύσης αντί να μαντέψεις αποτέλεσμα.
6. **Καθαρή εξαγωγή:** Μόνο έγκυρο JSON/JS χωρίς backticks.
7. **Ένα θέμα Τράπεζας = μία άσκηση:** Μέρη 2.1/2.2 ή α/β/γ στο ίδιο αντικείμενο.
8. **Ομάδες = υποενότητες:** Απαγορεύονται groups με id `tf`, `mc`, `match`, `blank`, `calc`.
9. **Δείκτες:** `Θέμα 2ο` / `Θέμα 4ο` (απλό κείμενο). **Απαγορεύεται** το `<sup>ο</sup>` στα strings.
10. **ΥΠΟΧΡΕΩΤΙΚΟ `stem` όταν υπάρχει εισαγωγική εκφώνηση/πρόβλημα:**
   Όταν μια άσκηση (ιδιαίτερα στα υπολογιστικά Θέματα 4ο ή σε Θέματα 2ο) ξεκινά με εισαγωγικό κείμενο, περιγραφή διάταξης ή κοινά δεδομένα ΠΡΙΝ τα υποερωτήματα (π.χ. «Σε μια κλιματιστική μονάδα ο αέρας εισέρχεται με θερμοκρασία $t_{db1} = 31\\text{ }^\\circ\\text{C}$... Με τη βοήθεια του ψυχρομετρικού χάρτη να υπολογίσετε:»):
   - **ΠΡΕΠΕΙ ΟΠΩΣΔΗΠΟΤΕ** να αντιγραφεί πλήρως όλη η εκφώνηση/περιγραφή στο πεδίο `"stem"`.
   - **ΑΠΑΓΟΡΕΥΕΤΑΙ** να παραλείπεται η εκφώνηση του προβλήματος και να ξεκινάει η άσκηση κατευθείαν από το «α) ...» χωρίς να ξέρει ο μαθητής τα δεδομένα!
   - Στο `stem` μην βάζεις απλώς τη λέξη «Θέμα 4ο». Βάλε το ουσιαστικό κείμενο του προβλήματος και τα δεδομένα του.
11. **ΑΥΣΤΗΡΗ ΔΙΑΤΗΡΗΣΗ ΑΡΙΘΜΗΣΗΣ ΥΠΟΕΡΩΤΗΜΑΤΩΝ (`subq` & `subqPrompt`) — ΟΧΙ ΑΥΘΑΙΡΕΤΗ ΔΙΑΣΠΑΣΗ:**
   - Κάθε item ΠΡΕΠΕΙ να περιέχει το πεδίο `"subq"` με τον επίσημο αριθμό υποερωτήματος του PDF (π.χ. `"2.1"`, `"2.2"`, `"2.3"`, `"4.1"`, `"4.2"`, `"4.3"`, `"4.4"` ή `"α"`, `"β"`, `"γ"`, `"δ"`).
   - Όταν ένα υποερώτημα έχει επιμέρους προτάσεις (π.χ. το 2.1 έχει προτάσεις Σωστό/Λάθος α, β, γ, δ) ή συμπλήρωση πίνακα (π.χ. 4.3 πίνακας καταστάσεων), δώσε σε ΟΛΑ τα επιμέρους items το **ίδιο** `"subq"` (π.χ. `"2.1"` ή `"4.3"`) και στο πρώτο από αυτά βάλε `"subqPrompt"` με την ακριβή εκφώνηση του υποερωτήματος. Έτσι το frontend τα εμφανίζει ενιαία κάτω από το «Ερώτημα 2.1» / «Ερώτημα 4.3» και ΔΕΝ τα σπάει σε «Ερώτημα 1 έως 10»!
12. **ΕΡΩΤΗΣΕΙΣ ΑΝΑΠΤΥΞΗΣ / ΑΙΤΙΟΛΟΓΗΣΗΣ (`"openEnded": true`):**
   - Όταν ένα υποερώτημα (π.χ. 2.2 «Με βάση τον ψυχρομετρικό χάρτη, να αιτιολογήσετε την απάντηση που δώσατε στην πρόταση δ. του 2.1», «Δικαιολογήστε την απάντησή σας στο γ.», «Να εξηγήσετε...») είναι ανοιχτής ανάπτυξης:
   - **ΑΠΑΓΟΡΕΥΕΤΑΙ** να παραλείπεται!
   - Δημιούργησε κανονικά το item με `"kind": "mc"`, `"openEnded": true`, `"subq"` τον κωδικό του (π.χ. `"2.2"`), `"prompt"` την ακριβή εκφώνηση του PDF, και ως σωστή επιλογή την επίσημη ΕΝΔΕΙΚΤΙΚΗ ΑΠΑΝΤΗΣΗ (με 2–3 αληθοφανείς λάθος επιλογές).
13. **ΣΧΕΔΙΑΣΤΙΚΑ ΕΡΩΤΗΜΑΤΑ ΠΑΝΩ ΣΕ ΧΑΡΤΗ / ΔΙΑΓΡΑΜΜΑ (`"kind": "open"`):**
   - Όταν ένα υποερώτημα ζητά να εντοπιστεί σημείο ή να σχεδιαστεί μεταβολή πάνω στον χάρτη (π.χ. «4.1 Εντοπίστε πάνω στο χάρτη και σημειώστε το σημείο...», «4.2 ...εντοπίστε το νέο σημείο και σχεδιάστε τη μεταβολή»):
   - **ΜΗΝ** το παραλείπεις και μην το συγχωνεύεις αλλού!
   - Καταχώρισέ το ως ξεχωριστό item με `"kind": "open"`, `"subq": "4.1"` (ή `"4.2"`), `"prompt"` την ακριβή εκφώνηση του PDF, και `"explain"` την επεξήγηση της λύσης.
14. **ΤΟΠΟΘΕΤΗΣΗ ΚΑΙ ΣΥΝΔΕΣΗ ΕΙΚΟΝΩΝ (`image` & `images`):**
   - Όταν ένα σχήμα ή διάγραμμα αφορά συγκεκριμένο υποερώτημα (π.χ. ερώτημα αντιστοίχισης 2.1, υπολογιστικό ερώτημα 4.2), τοποθετείται **αποκλειστικά** μέσα στο αντίστοιχο `item` (πεδίο `"image": "..."` ή `"images": [...]` για πολλαπλά σχήματα), και **ΟΧΙ** στο επίπεδο της άσκησης (`ex.image`).
   - Το πεδίο `ex.image` (στο επίπεδο της άσκησης) επιτρέπεται **μόνο** όταν το σχήμα αφορά κοινή εισαγωγική διάταξη ή ενιαίο ψυχρομετρικό χάρτη για όλα τα υποερωτήματα του `stem`.
   - Σε ερωτήματα αντιστοίχισης με σχήματα (π.χ. Σχήματα 1, 2, 3), όλα τα σχήματα αντιστοίχισης συγκεντρώνονται στον πίνακα `"images"` του συγκεκριμένου item αντιστοίχισης.
   - Απαγορεύεται η τοποθέτηση εικόνας σε άσχετο προηγούμενο ή επόμενο item (π.χ. διάγραμμα εξαρτημάτων μέσα σε ερώτημα Σωστού/Λάθους).
